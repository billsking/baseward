# 管理端功能

[English](admin-ui.md) | [简体中文](admin-ui.zh-CN.md)

- **仪表盘**：数据源数量/启用数、启用 Token 数、今日调用与拒绝数、最近 10 条审计。
- **数据源**：新建/编辑/删除、连接测试；保存前必须连接成功。**（v1.8）** 填默认库后「读取库清单」，从上游实际可见的非系统库中勾选可访问库（5.2）。
- **策略与脱敏**：数据源总开关 + 按库读写开关（5.3）；手动规则（库/表/列 + `mask/hash/null/off`），库为该数据源可访问库下拉，表与列输入支持下拉联想和模糊搜索；自动关键词说明。
- **Token**：创建（可选类型：常规/换发；可设置过期时间（也可永久有效）；可限定数据源/库/表/字段，明文仅一次）、查看过期时间与最近使用时间、编辑授权范围（不轮换明文，立即生效）、停用（立即生效）、删除。过期 Token 及其派生凭证都会被拒绝。
- **短期凭证**：查看换发令牌签发的短期凭证（行为人、来源 IP、到期、最后使用），可提前吊销（5.4）。
- **审计**：按时间（Asia/Shanghai 输入）、用户、数据源、状态、关键词筛选，50 条/页；列表与详情含「库」列（未记录时为 `—`），详情含完整 SQL、错误与拒绝原因。
- **设置**：修改密码（所有旧会话立即失效）、审计保留天数、立即清理过期审计、来源 IP 白名单（5.1）。
- **语言**：中英双语。首次访问按浏览器 `Accept-Language` 选择，右上角「中文 / EN」会记住选择（Cookie `gw_admin_lang`），也可用 `?lang=en` 显式切换；MCP 侧语言由 `GATEWAY_MCP_LANGUAGE` 决定。

所有已登录 POST 都校验 CSRF；会话 Cookie 为 `HttpOnly`、`SameSite=Lax`、`Path=/admin`，有效期 8 小时。

## 5.1 来源 IP 白名单

改白名单不再需要改环境变量并重启。设置页对两个入口各给一个文本框（每行一个 IP 或 CIDR，也接受逗号分隔），保存即整段替换、5 秒内对新建连接生效：

| 入口 | 取值来源 | 都没配置时 | 白名单外的表现 |
| --- | --- | --- | --- |
| MySQL 导出通道 | TCP 对端地址，**不可伪造** | 拒绝所有连接 | 握手前直接断开，审计 `IP_NOT_ALLOWED` |
| MCP 入口（`/mcp`） | `X-Forwarded-For` 首个地址，网关直接对外时可伪造 | 不限制来源 | 403 `ip_not_allowed`，且**先于** Token 校验 |

- **DB 优先**：一旦在设置页保存过，该入口就只认 DB 的值，环境变量里的同名项不再生效。每个文本框下方都提示当前生效来源与条数（本页已保存 / 环境变量 `GATEWAY_*` / 不限制或拒绝所有），`/healthz` 用 `allowlist_source`（`db` / `env` / `unset`）和 `allowlist_entries` 同步暴露同一份状态。
- **`/admin` 不受白名单限制**：改错了还能进设置页改回来，这是唯一的人工兜底路径。
- **空名单是「拒绝」不是「不限制」**（导出通道）：清空并保存 = 所有导出连接一律被拒，进程照常运行。因此不再有「开启导出而白名单为空则拒绝启动」的启动门禁——崩溃循环会让运维进不了正是用来修复它的页面。
- **保存时按严格口径校验**：`192.168.1.5/24` 这种带主机位的写法会被拒绝并提示改写成起始地址（历史上环境变量走宽松口径，会把主机位静默展成整个 /24，等于悄悄放宽）。非法项、条数超过 50、单条超过 64 字符同样拒绝保存。
- **每次变更进审计**：`event_type=setting_change`，`deny_reason` 记录 `旧值 ⇒ 新值`；与当前值完全一致的重复保存不写库、不产生审计。
- 读 DB 失败时沿用最近一次成功加载的值（无缓存则拒绝），不会出现「数据库抖一下白名单就空了」。

## 5.2 多库数据源与可访问库（v1.8）

一个数据源仍然对应一台主机 + 一套连接账号，但可以暴露同一实例里的多个库：

1. 新建/编辑数据源时先填**默认库**，点「读取库清单」——网关只列上游实际存在、且不在系统库清单里的库。清单是 `mysql` / `information_schema` / `performance_schema` / `sys` / `metrics_schema` / `oceanbase`，按大小写不敏感比较（TiDB 用大写库名、OceanBase 有自有系统库）；清单之外的引擎内部库仍会出现，逐引擎差异见 [compatibility.zh-CN.md](compatibility.zh-CN.md)。
2. 勾选**可访问库**后保存。默认库必须在可访问库中；可访问库不设数量上限，清单支持按名称过滤与全选/清空。
3. 编辑页展示已保存清单与其读写策略（不依赖上游在线）；刷新时提示「上游新增 N 个 / 已不存在 M 个」，已不存在的库标红可移除。

**口径**

- **可访问库是网关级暴露面**：未勾选的库即使数据库账号有权限，网关也不返回、不执行——元数据、`execute_sql`、导出通道、脱敏规则与管理端联想一律不可见（fail-closed）。
- **可用库 = 可访问库 ∩ Token 已授权库**，由同一函数计算；`list_datasources` / `describe_datasource` 的 `databases[]`、签发页候选库与错误提示共用这份结果。
- **升级兼容**：升级前已存在、尚未写库清单的数据源按「只暴露默认库」处理，行为与 v1.7 一致；在管理端保存一次清单后即转入多库模式。
- 库清单读取失败时新建表单禁止保存，不提供手填库名入口（避免把拼写错误带进配置）。
- 从可访问库移除某个库会即时生效：Token 中该库的授权配置保留但立即失效，目标库为该库的导出凭证下一条语句即被拒，库级策略行随库删除；重新加入该库时默认只读、不继承历史策略。

## 5.3 按库读写策略（v1.8）

- 数据源总开关 `is_read_only` 保留为**上位强制只读**：总开关只读时任何库都不能写。**实际可写 = 总开关可写 AND 库级可写**。
- 每个可访问库单独设置只读/可写；新建、新增或重新加入的库默认只读。
- 只读库禁止 INSERT/UPDATE/DELETE/REPLACE；写语句有多个目标库时任一为只读即拒绝，消息点名第一个只读目标库。从只读库读取（如 `INSERT ... SELECT`）不受影响——读写策略只约束**写目标**。
- 任一库或总开关由只读改可写需勾选二次确认，保存后立即生效；收紧为只读不需确认。
- 每次实际变更写一条 `policy_change` 审计，多库变更合并为一条，内容形如 `总开关：只读 ⇒ 可写；report：只读 ⇒ 可写`；值未变的重复保存不写库、不产生审计。
- 数据源列表徽标显示「全部只读」或「可写 N 个库」；总开关只读时，库级设为可写仍会保存（作为预配置），页面显示「只读（总开关）」。

## 5.4 令牌类型与短期凭证

- **令牌类型**：创建 Token 时选「常规（可访问数据源）」或「换发（仅换短期凭证）」。类型创建后不可改；列表与编辑页显示类型徽标。
- **换发型约束**：行为人策略固定为 `require`，创建时选 ignore 会被强制为 require，编辑页改回 ignore 会被拒绝并提示。换发型令牌不能查库、不能签发导出凭证；它的授权范围就是换发出的短期凭证的权限上限。
- **短期凭证页**：列出凭证前缀、所属换发令牌、行为人（id/昵称/provider）、来源 IP、到期时间、最后使用时间与状态（有效/已过期/已吊销）。可提前吊销，吊销后立即生效并写审计。
- **自动取代与清理**：同一换发令牌 + 同一行为人再次换发时，旧的有效凭证立即被吊销；过期行每日 03:00 随审计清理删除。
- 契约与端点细节见 [短期凭证换发](exchange-credential.zh-CN.md)。
